# Guia para padronizar o projeto em JavaScript

Este arquivo mostra como deixar o projeto inteiro em JavaScript, sem arquivos .ts, mantendo o Prisma e o Express funcionando corretamente.

## 2. Instalar dependências

```powershell

npm install express cors dotenv @prisma/client @prisma/adapter-pg pg
npm install --save-dev prisma nodemon
```

```powershell

```

## 3. Configurar o package.json

Arquivo: `server/package.json`

```json
{
  "name": "server",
  "version": "1.0.0",
  "type": "module",
  "main": "server.js",
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  },
  "dependencies": {
    "@prisma/adapter-pg": "^7.10.0",
    "@prisma/client": "^7.10.0",
    "cors": "^2.8.5",

  "devDependencies": {
    "nodemon": "^3.1.14",
    "prisma": "^7.10.0"
  }
}
```

Importante: se o projeto for puro JavaScript, não precisa de `tsx` e nem de `@types/node`.

## 4. Configurar o arquivo .env

Arquivo: `server/.env`

```env

```

## 5. Configurar o Prisma em JS

O ideal, para ficar tudo em JavaScript, é usar um arquivo `prisma.config.js` ao invés de `prisma.config.ts`.

Arquivo: `server/prisma.config.js`

```js
import "dotenv/config";
import { defineConfig } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: process.env.DATABASE_URL,
  },
});
```

Se quiser manter tudo em JS puro, é melhor remover o arquivo `.ts` e usar o `.js`.

## 6. Ajustar o schema.prisma

Arquivo: `server/prisma/schema.prisma`

```prisma
generator client {
  provider = "prisma-client"
}

datasource db {
  provider = "postgresql"
}

model Professor {
  id        Int      @id @default(autoincrement())
  nome      String
  email     String   @unique
  materia   String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  alunos    Aluno[]
}

model Aluno {
  id        Int         @id @default(autoincrement())
  nome      String
  email     String      @unique
  matricula String      @unique
  createdAt DateTime    @default(now())
  updatedAt DateTime    @updatedAt

  professores Professor[]
}
```

Se quiser simplificar ainda mais, pode remover a configuração `output = "../generated/prisma"`.

Isso evita importações estranhas como `./generated/prisma/client.ts` e usa o cliente padrão do Prisma:

```js
import { PrismaClient } from "@prisma/client";
```

## 7. Gerar o cliente Prisma

Depois de configurar o banco e o `.env`, rodar:

```powershell
npx prisma validate
npx prisma generate
npx prisma migrate dev --name cria_alunos_e_professores
```

Se o banco já estiver pronto, pode usar somente:

```powershell
npx prisma generate
```

## 8. Criar o servidor em JavaScript

Arquivo: `server/server.js`

```js
import express from "express";
import cors from "cors";
import dotenv from "dotenv";
import { PrismaClient } from "@prisma/client";
import { PrismaPg } from "@prisma/adapter-pg";

dotenv.config();

const adapter = new PrismaPg({
  connectionString: process.env.DATABASE_URL,
});

const prisma = new PrismaClient({ adapter });

const app = express();
app.use(cors());
app.use(express.json());

const PORT = process.env.PORT || 3003;

app.get("/", (req, res) => {
  res.send("Servidor rodando com sucesso!");
});

app.get("/alunos", async (req, res) => {
  try {
    const alunos = await prisma.aluno.findMany();
    res.json(alunos);
  } catch (error) {
    console.error(error);
    res.status(500).json({ error: "Erro ao buscar alunos" });
  }
});

app.listen(PORT, () => {
  console.log(`Servidor rodando na porta ${PORT}`);
});
```

## 9. Executar o servidor

Modo desenvolvimento:

```powershell
npm run dev
```

Modo normal:

```powershell
npm start
```

## 10. Testar a API

Abrir outro terminal:

```powershell
Invoke-WebRequest -UseBasicParsing http://localhost:3003/
Invoke-WebRequest -UseBasicParsing http://localhost:3003/alunos
```

Resposta esperada da rota principal:

```text
Servidor rodando com sucesso!
```

Se não houver alunos cadastrados, a rota `/alunos` deve retornar:

```json
[]
```

## 11. Vantagens do padrão JavaScript

- menos configuração de TypeScript
- evita erro de `process` sem `@types/node`
- menos arquivos `.ts` no projeto
- mais simples para quem está começando

## 12. Quando usar TypeScript

Use TypeScript se o objetivo for:

- projetos maiores
- melhor tipagem
- organização mais robusta
- integração com equipes que usam TS

Mas para esse projeto em aula, padronizar tudo em JS costuma ser mais simples e mais fácil de manter.

## 14. Resumo prático

Se o objetivo for padronizar tudo em JavaScript, o mais correto é:

1. trocar `prisma.config.ts` para `prisma.config.js`
2. remover ou evitar imports de arquivos `.ts` gerados
3. usar `@prisma/client` no servidor
4. manter o projeto sem `tsx`, sem `tsconfig.json` e sem `@types/node`
5. rodar o servidor com `node server.js` ou `nodemon server.js`

Esse é o caminho mais limpo para um projeto 100% JS.
