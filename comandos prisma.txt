# Guia do projeto Prisma + Express + PostgreSQL

Este arquivo explica como configurar e rodar o servidor do projeto que está em:
`Trabalho Prisma_ORM/server`

## 1. Pré-requisitos

Verifique se o Node e o npm estão instalados:

```powershell
node --version
npm --version
```

Também é necessário ter o PostgreSQL instalado e em execução.

Banco usado no projeto:

```text
Banco: trabalho_web
Usuário: postgres
Senha: postgres
Host: localhost
Porta: 5432
```

Se necessário, crie o banco:

```sql
CREATE DATABASE trabalho_web;
```

## 2. Entrar na pasta do servidor

Todos os comandos do Prisma, npm e do servidor devem ser executados dentro de `server`:

```powershell
cd "c:\Users\User\OneDrive\Documentos\FACULDADE - CIÊNCIAS DA COMPUTAÇÃO\5° QUINTO SEMESTRE CC\Programação WEB\Trabalho Prisma_ORM\server"
```

Ou, se estiver dentro da pasta do projeto:

```powershell

```

## 3. Instalar dependências

Se o projeto ainda não estiver com as dependências instaladas:

```powershell
npm install express cors dotenv @prisma/client @prisma/adapter-pg pg
npm install --save-dev prisma nodemon tsx @types/node
```

Função dos principais pacotes:

- `express`: servidor HTTP
- `cors`: permite acesso de frontend
- `dotenv`: lê variáveis do `.env`
- `prisma`: CLI do Prisma
- `@prisma/client`: cliente Prisma
- `@prisma/adapter-pg`: adapter PostgreSQL exigido pelo Prisma 7
- `pg`: driver do PostgreSQL
- `tsx`: executa arquivos TypeScript
- `nodemon`: reinicia o servidor automaticamente
- `@types/node`: tipagens do Node

## 4. Configurar TypeScript e Node

Se o VS Code mostrar erro como:

```text
Cannot find name 'process'. Do you need to install type definitions for node?
```

instale as tipagens:

```powershell
npm i -D @types/node
```

Arquivo: `server/tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "types": ["node"],
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "resolveJsonModule": true
  },
  "include": ["**/*.ts", "**/*.js"]
}
```

Isso resolve erros em `prisma.config.ts` e em arquivos que usam `process.env`.

## 5. Configurar o arquivo .env

Arquivo: `server/.env`

```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/trabalho_web?schema=public"
PORT=3003
```

Se a senha do PostgreSQL for outra, trocar o valor.

## 6. Configurar Prisma

Arquivo: `server/prisma.config.ts`

```ts
import "dotenv/config";
import { defineConfig } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: process.env["DATABASE_URL"],
  },
});
```

## 7. Configurar o schema Prisma

Arquivo: `server/prisma/schema.prisma`

```prisma
generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Professor {
  id        Int      @id @default(autoincrement())
  nome      String
  email     String   @unique
  materia   String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  alunos    Aluno[]
}

model Aluno {
  id        Int      @id @default(autoincrement())
  nome      String
  email     String   @unique
  matricula String   @unique
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  professores Professor[]
}
```

Observação:
- o Prisma 7 gera o cliente em `server/generated/prisma`
- essa pasta é criada automaticamente e não deve ser mexida manualmente

## 8. Criar as tabelas e gerar o cliente

Executar:

```powershell
npx prisma format
npx prisma validate
npx prisma migrate dev --name cria_alunos_e_professores
npx prisma generate
```

Explicação:
- `migrate dev` cria a migration e aplica as tabelas no PostgreSQL
- `generate` gera os arquivos do cliente Prisma

Se o banco já estiver inicializado e você quiser só validar:

```powershell
npx prisma migrate status
npx prisma validate
```

## 9. Configurar o package.json

Arquivo: `server/package.json`

```json
{
  "type": "module",
  "scripts": {
    "start": "node server.js",
    "start:dev": "nodemon --exec tsx server.js"
  }
}
```

Importante:
- não usar `node server.js` sem `tsx` em projetos com Prisma 7
- `nodemon server.js` também pode gerar erro por arquivos `.ts`

## 10. Criar o servidor

Arquivo: `server/server.js`

```js
import express from "express";
import cors from "cors";
import dotenv from "dotenv";
import { PrismaClient } from "./generated/prisma/client.ts";
import { PrismaPg } from "@prisma/adapter-pg";

dotenv.config();

const adapter = new PrismaPg({
  connectionString: process.env.DATABASE_URL,
});

const prisma = new PrismaClient({ adapter });

const app = express();
app.use(cors());
app.use(express.json());

const PORT = process.env.PORT || 3003;

app.get("/", (req, res) => {
  res.send("Servidor rodando com sucesso!");
});

app.get("/alunos", async (req, res) => {
  try {
    const alunos = await prisma.aluno.findMany();
    res.json(alunos);
  } catch (error) {
    console.error(error);
    res.status(500).json({ error: "Erro ao buscar alunos" });
  }
});

app.listen(PORT, () => {
  console.log(`Servidor rodando na porta ${PORT}`);
});
```

Mudanças importantes:
1. importar `cors` antes de `app.use(cors())`
2. importar `PrismaClient` de `./generated/prisma/client.ts`
3. importar `PrismaPg` de `@prisma/adapter-pg`
4. criar o adapter com `DATABASE_URL`
5. criar o Prisma Client com `{ adapter }`
6. carregar o `.env` antes de usar as variáveis
7. rodar com `tsx` no modo desenvolvimento

Não usar esse padrão antigo:

```js
const { PrismaClient } = prismaPkg;
```

ou:

```js
const prisma = new PrismaClient();
```

Isso gera erro no Prisma 7 sem adapter PostgreSQL.

## 14. Diagnóstico de erros comuns

### `ENOENT package.json`

Você executou o comando na pasta errada. Entre em `server` antes do `npm`.

### `ERR_UNKNOWN_FILE_EXTENSION: .ts`

Foi executado com `node server.js` ou `nodemon server.js` sem `tsx`.

Use:

```powershell
npm run start:dev
```

### `Cannot find name 'process'`

Falta instalar as tipagens do Node:

```powershell
npm i -D @types/node
```

e ter `tsconfig.json` com:

```json
{
  "compilerOptions": {
    "types": ["node"]
  }
}
```

### `A driver adapter is required`

Faltou instalar ou configurar o adapter PostgreSQL:

```powershell
npm install @prisma/adapter-pg pg
```

Verificar se o `server.js` contém:

```js
const adapter = new PrismaPg({
  connectionString: process.env.DATABASE_URL,
});
const prisma = new PrismaClient({ adapter });
```

### Erro de conexão com PostgreSQL

Verificar:
- serviço do PostgreSQL está ativo
- banco `trabalho_web` existe
- DATABASE_URL está correta
- usuário e senha estão certos

### `Erro ao buscar alunos` na rota /alunos

Executar:

```powershell
npx prisma migrate status
npx prisma validate
```

Se a tabela não existir, o Prisma ainda não criou as estruturas no banco.
